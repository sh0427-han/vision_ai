01 · IMAGE & TENSOR

이미지는 어떻게 숫자가 될까?

픽셀, RGB, 텐서, 정규화. 모델에 들어가는 입력을 숫자의 관점에서 이해합니다.

기초 개념예상 학습 15분수치 예시 · 직접 그린 도식

사람의 장면을 모델의 배열로 바꾸기

컴퓨터 비전 모델이 받는 것은 “사진”이라는 개념보다 정해진 순서로 배치된 숫자 배열에 가깝습니다. 사진을 읽으면 높이·너비·색상 채널의 배열이 되고, 여러 장을 묶으면 배치 차원이 추가됩니다. 모델은 이 수치에서 학습한 패턴을 이용해 클래스, 좌표, 마스크 등을 예측합니다.

예를 들어 RGB 이미지 224 × 224 한 장은 150,528개의 채널 값을 가집니다. 32장을 묶으면 입력은 [32, 3, 224, 224]입니다. 배열의 숫자 개수와 모델이 학습하는 파라미터 개수는 서로 다른 개념입니다.

한 픽셀에는 무엇이 들어 있을까?

표현자료 구조 예시의미
Grayscale[H, W] · 8-bit 값 0~2550은 검정, 255는 흰색. 밝기 하나로 표현합니다.
RGB[H, W, 3] · [220, 60, 30]R, G, B 채널의 세기. 이 예시는 붉은색 계열입니다.
배치 텐서[32, 3, 224, 224]PyTorch CNN에서 흔한 NCHW 순서: 배치, 채널, 높이, 너비.

OpenCV로 읽은 컬러 이미지의 기본 순서는 BGR입니다. RGB로 학습한 모델에 BGR을 그대로 넣으면 빨강과 파랑의 의미가 바뀝니다. 또한 reshape로 채널 순서를 바꾸면 안 됩니다. 차원의 위치를 바꾸는 transpose나 permute가 필요합니다.

형태와 의미를 함께 확인

1920 × 1080 이미지를 보통 너비 × 높이로 말하지만 배열은 흔히 [1080, 1920, 3]입니다. “shape가 맞다”는 것만으로 RGB 순서와 값 범위가 맞는지는 알 수 없습니다.

직접 확인하기: 모양은 같아도 숫자는 달라진다

아래 8 × 8 밝기 패턴은 학습용 합성 입력입니다. 왼쪽 그림과 오른쪽 행렬은 동일한 64개 픽셀을 보여 줍니다. 밝기 배율을 바꾸면 경계와 내부의 서로 다른 값들이 함께 변합니다.

밝기와 픽셀 값

INTERACTIVE

표시값 = clip(round(원래 값 × 배율), 0, 255). 실제 카메라의 노출·감마·노이즈를 모두 재현하는 물리 모델은 아닙니다.

밝은 값이 255를 넘으면 잘려서 포화됩니다. 예를 들어 170 × 1.8 = 306은 255가 됩니다. 서로 다른 원래 값들이 같은 255가 되므로 정보가 사라질 수 있습니다. 조명 변화에 강한 모델을 만들려면 이런 입력 분포 변화와 촬영 조건을 함께 생각해야 합니다.

스케일 변환과 정규화는 구분하기

uint8 → float32 → 255로 나누기는 0~255를 0~1로 바꾸는 스케일 변환입니다. 이후 채널별 평균과 표준편차를 이용하는 표준화가 추가될 수 있습니다. 전처리는 사용한 사전학습 가중치와 학습 조건을 따라야 합니다.

x_scaled = x_uint8 / 255 x_normalized = (x_scaled − mean) / std

가상의 한 채널에서 픽셀 128, 평균 0.5, 표준편차 0.25라면 (128/255 − 0.5)/0.25 ≈ 0.00784입니다. 정규화 결과는 음수일 수 있습니다. 평균·표준편차가 [0.5, 0.25]라는 뜻이 아니라 각각 하나의 채널에 대해 정한 예시입니다.

기억할 핵심

입력 크기·채널 순서·dtype·값 범위·정규화는 하나의 계약입니다. 학습과 추론이 같은 계약을 사용해야 합니다.

스스로 설명해 보기

224 × 224 RGB 이미지의 채널 값은 왜 50,176개가 아닐까?

224 × 224 = 50,176은 공간 위치의 수입니다. 각 위치에 3개 채널이 있으므로 150,528개 값입니다.

배치 크기를 16에서 32로 바꾸면 모델 파라미터도 두 배가 될까?

파라미터 수는 그대로입니다. 한 번에 처리하는 입력과 중간 활성값의 양이 늘기 때문에 보통 메모리 사용량이 증가합니다.
